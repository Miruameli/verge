### Published artifacts

```
SHA256SUMS
verge-0.1.0-x86_64-unknown-linux-gnu.tar.gz
verge-0.1.0-aarch64-unknown-linux-gnu.tar.gz
verge-0.1.0-aarch64-apple-darwin.tar.gz
verge-0.1.0-x86_64-pc-windows-msvc.zip
verge-<target>.cdx.json   (SBOM CycloneDX 1.5 for the four targets)
```

### Evidence

- `sha256sum -c --strict SHA256SUMS` passed for all eight files after
  re-downloading them from the GitHub Release.
- The SBOM contains 13 components for linux/macOS and 11 for Windows, with
  `verge-core` as the main component and `sha2` recorded.
- The `aarch64-unknown-linux-gnu` binary from the release runs a real flow:
  `init → import → commit → log → show <old commit>` returns different contents
  per revision.
- Four release runs failed before one succeeded; every failure was fixed in its
  own PR and recorded in a commit:
  1. the aarch64 cross-linker was not pointed (`file in wrong format`),
  2. the minor version `0.5` is invalid and `zip` is missing on the Windows runner,
  3. the linker env was set on the wrong step,
  4. the SBOM output location was not found, so the SBOM went missing from the release.

### Compliance notes

- A tag only ever points at a commit on `main` that is already green; a tag move
  is recorded in the repository audit trail.
- The release is published only after `sha256sum --check --strict` accepts every
  checksum; the publish job fails if a single one does not match.
- The SBOM is generated from `cargo metadata --locked --filter-platform` so it is
  reproducible and recorded in the lockfile.
